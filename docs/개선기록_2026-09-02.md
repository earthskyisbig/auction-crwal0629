### 7-3. 서울 구별 파이프라인 (`realprice_서울구별/`)
- **해제거래 원본행 잔존** (실데이터 검증: 강남구 O행 546개 중 341개가 동일 내용의 빈값 쌍둥이 행): O행만 버려 해제된 거래 원본이 통계에 남아 있었다. 공용 로더 `sales_io.load_sales()` 가 (월·동·단지·면적·금액·층·일) 그룹에 O 가 있으면 통째로 버리고 완전 중복도 제거. 5개 분석 스크립트가 전부 이 로더를 쓴다.
- **리포트 서술 하드코딩**: "2024.09~2025.02 대비 2026.03~08", 전세가율 39~40%/62~64%, 성수 +33%·금호3가 +57%, 서초 −5.4%·양천 −10.7%, "2026년 7~8월", 인구 "2026.07" 등이 코드에 박혀 다음 분기 갱신 때 차트와 어긋날 상태였다. 전부 데이터(insights/matched/jeonse/belt_dong/population `asof`)에서 생성. 차트 축(라인 ymax 13000, 산점도 12500/40, 중앙선 5000/21.4, 히트맵 ÷38)도 데이터로 계산.
- **이번 달 포함 창**: `windows.py` 종료를 지난달로 변경. 수집 완료 시 `windows_manifest.json` 을 남겨 단독 실행 시 CSV 와 기간이 어긋나지 않게 함.
- **동명 단지 혼입**: 매칭 지수·전세가율 키에 법정동 추가. 파인더 K-apt 매칭은 (법정동, 이름) → 이름+준공연도 ±1 → 단일 후보 → 같은 동 부분일치 순.
- **전세 갱신 계약 포함**: 갱신은 +5% 상한이라 전세가율을 낮춘다. 신규 계약만 사용.
- **None 크래시**: 매칭 쌍·전세 쌍 부족으로 None 이 나오면 리포트·지도가 TypeError 로 죽던 경로 전부 가드(회색 표시). 음수 상승률 `+-3.2%` 표기 정정.
- **운영**: `refresh_all.sh` 가 수집 전 CSV 를 지우던 것을 `_prev/` 백업 + 실패 시 복원으로. API 키 없으면 즉시 종료(종전엔 35초씩 재시도 후 오류). `collect_population.py` 가 기준월 `asof` 를 기록. 파인더 템플릿의 "2026.08 기준" 고정 문구 → 빌드 날짜.
- **실행 확인**: 기존 24개월 CSV 로 분석 5단계 + 리포트 + 파인더 빌드를 실제 실행. 강남구 거래 6,494 → 6,100건(해제 쌍둥이 제거), 매칭 지수 17.7 → 17.8%, 전세가율 39.8 → 39.5%(쌍 329 → 220, 갱신 제외). 25개 구 모두 None 없음.
- 손대지 않음: 1% 이상치 컷을 24개월 전체가 아닌 월별로 하는 방안(추세 편향 가능성은 인정하나 리포트 수치 변화가 커서 사용자 결정), 종사자수 5개 구 수동값.

## 8. 후속 — 단지별 리포트 신설 (같은 날)

- `realprice_서울구별/compute_complex.py`: 구별 매칭 지수를 단지 단위(구·법정동·단지명, 평형=전용 정수)로 계산. 대표 평형(최근 6개월 최다 거래)의 매매 중앙가·신규 전세 중앙가·전세가율·갭, K-apt 세대수·준공 결합 → `complex_index.json`.
- `build_complex_report.py` → `seoul_complex_report.html`: 상승 상위 30, 구별 최고 평당가·상승 1위 단지 표, 평당가×상승률×세대수 사분면, 1,000세대 이상 상위 20, 갭 작은 25곳, 하위 15, 1,702개 단지 전체 표(구 칩·검색·정렬·스파크라인). 순위는 쌍 2개·거래 12건 이상(658개)만.

## 9. 후속 — 3D 평당가 지형 타임랩스 (같은 날)
